## Параметры и трассы

Причины пропусков: listener не записывал bindings; currentTraceId отвергал несэмплированный контекст; консольные команды не создавали трассу; отключение экспорта отключало также контекст очередей и HTTP. Старый адрес collector не соответствует существующему внешнему Tempo. Read-only wrapper использует отдельное окружение и показал tracing_enabled=false; реальные переменные API через этот доступ недоступны. Это значение не доказывает, что экспорт выключен в API.

Добавлены bindings с позициями и типами, исходный размер SQL, fingerprint, уровень транзакции, путь/строка вызова, название команды или задания и UUID задания. ID, даты и статусы сохраняются; произвольные строки, JSON и чувствительные запросы редактируются. Максимум 100 bindings, присутствует признак усечения. Строковые SQL-литералы редактируются до усечения SQL. Секреты и содержимое файлов в трассы не передаются.

HTTP и задания имеют валидный trace_id даже без экспорта. В журнале trace_sampled отличает выбранную для экспорта трассу от ID для связи журналов; это не подтверждение доставки. При включённом экспорте каждый медленный SQL вне основной 10% выборки создаёт отдельную трассу с link и parent_trace_id. Контекст HTTP имеет приоритет над консольной командой Octane и очищается после ответа/ошибки. Контекст задания очищается перед следующей работой.

В production экспорт включается по умолчанию, адрес по умолчанию — существующий приватный OTLP Tempo. Явные OTEL_TRACING_ENABLED / OTEL_TRACING_ENDPOINT сохраняют приоритет. Приёмник проверен read-only GET, ответ 405 ожидаем для POST endpoint. Доставка трасс после выпуска должна проверяться отдельно.
