# Ускорение каталога и чтение пустых workforce-отчётов

## Контекст

Production-каталог отчётов отвечает за 4–5 секунд, поскольку одинаковые проверки прав повторяются для каждого опубликованного отчёта и каждого факта области доступа. Admin дополнительно инициирует два одинаковых запроса каталога.

Запуск `attendance_execution` успешно переходит в `ready`, но чтение пустых строк возвращает `REPORT_INTERNAL_ERROR`: общий workforce query service объявляет выходную drill-down колонку `drill`, отсутствующую в опубликованном контракте этого отчёта.

## Решение

### Backend: каталог

Внутри одного вызова `authorizeCatalog` мемоизировать результат проверки по ключу `permission + canonical facts`. Проверки организации, проектов и ресурсов остаются обязательными; переиспользуется только уже вычисленное решение для идентичного набора входных данных. Межзапросный кеш не вводится, поэтому изменение прав применяется со следующего HTTP-запроса.

### Backend: строки

Drill-down token mapping должен принадлежать конкретному опубликованному контракту. Workforce query service не должен безусловно объявлять `drill`. Для отчётов без этой выходной колонки mapping пустой; для отчётов с drill-down используется существующая явная колонка контракта. Пустая страница `attendance_execution` должна возвращаться успешно.

### Admin

Все потребители каталога используют один query key и один общий запрос в рамках жизненного цикла страницы. Повторная загрузка разрешена только после явной инвалидации или истечения установленного stale window. Контракт ответа не меняется.

## Ошибки и безопасность

- Проверки RBAC/ABAC не удаляются и не ослабляются.
- Ошибка отдельной проверки прав по-прежнему закрывает доступ.
- Не добавляется долгоживущий кеш разрешений.
- Не меняются API payload, маршруты и пользовательские сообщения.

## Проверки

- RED/GREEN backend-тест: пустая страница `attendance_execution` проходит полный `GetReportRowsHandler` без `REPORT_INTERNAL_ERROR`.
- RED/GREEN backend-тест: одинаковая permission/facts-проверка каталога вычисляется один раз, различающиеся факты проверяются отдельно.
- RED/GREEN admin-тест: два потребителя каталога инициируют один сетевой запрос.
- PHP syntax, целевой PHPUnit, Larastan изменённых PHP-файлов.
- TypeScript, ESLint/Prettier изменённых файлов, целевой Vitest.
- После merge: штатные deploy workflow и production smoke по времени каталога и пустым строкам.

## Границы

Миграции, новые очереди, изменение публикации отчётов, глобальный кеш прав и широкая переработка reporting-модуля не входят в задачу.
