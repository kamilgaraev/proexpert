# Единый контракт аватара администратора

## Проблема

Страница настроек получает подписанный `avatar_url` из профильного API, а шапка админки повторно загружает пользователя через `/api/v1/admin/auth/me`. Этот endpoint и вход возвращают необработанную модель `User`, поэтому наружу попадает внутренний `avatar_path`, но отсутствует вычисляемый `avatar_url`. В результате профиль показывает изображение, а шапка — первую букву имени.

## Решение

- Backend возвращает пользователя из `login` и `/auth/me` через отдельный `AdminAuthUserResource`, сохраняя прежние публичные поля auth-payload.
- Публичный контракт содержит `avatar_url` и не раскрывает внутренний `avatar_path`.
- `AuthContext` остаётся единственным владельцем текущего пользователя в админке.
- `Layout` читает пользователя и состояние загрузки из `AuthContext`, не выполняет отдельный запрос `/auth/me`.
- После сохранения профиля страница передаёт обновлённые поля пользователя в `AuthContext`; шапка обновляется сразу без перезагрузки.

## Поток данных

1. При старте `AuthProvider` обновляет сессию и один раз вызывает `/auth/me`.
2. Backend сериализует пользователя через `AdminAuthUserResource`, включая короткоживущий подписанный `avatar_url`.
3. `Layout` отображает аватар из `AuthContext.user.avatar_url`.
4. Профиль после успешного сохранения объединяет ответ API с текущим пользователем в контексте.

## Безопасность и совместимость

- Внешний URL остаётся подписанным и ограниченным по времени существующей серверной логикой.
- Ключ объекта `avatar_path` не передаётся auth-endpoint-ами.
- Формат верхнего ответа `AdminResponse` и токены не меняются.
- Клиенты без аватара продолжают получать `avatar_url` по правилам существующего accessor пользователя.

## Проверка

- Регрессионный backend-тест фиксирует наличие `avatar_url` и отсутствие `avatar_path` в `/auth/me`.
- Регрессионные frontend-тесты фиксируют обновление пользователя в `AuthContext` и передачу результата сохранения профиля в контекст.
- Целевые проверки: PHPUnit без обращения к БД, Vitest, TypeScript и lint изменённых файлов.
