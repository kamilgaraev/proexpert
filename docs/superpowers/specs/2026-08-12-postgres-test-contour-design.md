# PostgreSQL-контур тестов backend МОСТ

## Цель

Добавить воспроизводимый локальный запуск выбранных Laravel-тестов на PostgreSQL 16 в Docker, не затрагивая рабочую или production-базу и не меняя существующий быстрый SQLite-контур по умолчанию.

## Выбранный подход

Использовать отдельный Docker Compose-файл для тестового PostgreSQL и отдельную PHPUnit-конфигурацию. Запуск обернуть PowerShell-скриптом, который проверяет окружение, поднимает контейнер, ожидает готовность базы и только затем запускает переданный тест.

Существующий контейнер контрактов генерации смет не переиспользуется: у него специальная модель ролей, фиксированный порт и собственные проверки целостности окружения.

## Компоненты

### Docker Compose

Отдельный файл поднимает `postgres:16-alpine` на loopback-интерфейсе и отдельном нестандартном порту. База, пользователь и пароль имеют только тестовые значения. Добавляется healthcheck через `pg_isready` и отдельный Docker volume для ускорения повторных локальных запусков.

### PHPUnit

Отдельный `phpunit.postgres.xml` наследует состав основного тестового контура, но задаёт `DB_CONNECTION=pgsql` и параметры тестового контейнера. Текущий `phpunit.xml` с SQLite остаётся без изменений, поэтому существующие команды не ломаются.

### Безопасный launcher

PowerShell-скрипт:

1. Проверяет доступность Docker daemon.
2. Проверяет, что имя базы явно тестовое.
3. Поднимает только тестовый compose-проект.
4. Ждёт успешного healthcheck с ограниченным таймаутом.
5. Запускает один переданный PHPUnit test path через PostgreSQL-конфигурацию.
6. Возвращает exit code PHPUnit и не выполняет ручные миграции.

Контейнер по умолчанию остаётся запущенным для быстрых повторных прогонов. Для явной очистки используется отдельная стандартная команда Docker Compose `down -v`; launcher данные сам не удаляет.

### Composer-команда

Добавляется короткая команда `test:postgres`, вызывающая launcher. Путь конкретного теста можно передать launcher напрямую; массовый прогон не является частью первой проверки.

### Git ignore

В `.gitignore` добавляется исключение для локального файла переопределений `.env.testing.local`. PHPUnit cache уже исключён, а данные PostgreSQL хранятся в именованном Docker volume и не создают каталог в репозитории.

Общие файлы `compose.testing.yml`, `phpunit.postgres.xml` и launcher должны отслеживаться Git. Поскольку текущий `.gitignore` содержит широкое правило `*.xml`, для `phpunit.postgres.xml` добавляется явное разрешающее правило.

## Изоляция данных

- Порт публикуется только на `127.0.0.1`.
- Имя базы оканчивается на `_testing`.
- Учётные данные предназначены только для локального контейнера.
- Launcher не принимает произвольные production-подключения.
- Laravel `RefreshDatabase` создаёт схему внутри выделенной тестовой базы.
- Параллельный PHPUnit пока не включается: его следует добавлять отдельным этапом с отдельной базой на каждый process token.

## Проверка

Сначала добавляется архитектурный тест конфигурации, который должен упасть до появления файлов контура. После реализации проверяются:

1. Синтаксис Compose-конфигурации через `docker compose config`.
2. Защитные условия launcher без обращения к рабочей БД.
3. Один небольшой Laravel-тест с `RefreshDatabase` на реальном PostgreSQL 16.
4. Фактический драйвер внутри тестового процесса должен быть `pgsql`.

Первый прогон не включает полный набор тестов: его задача — доказать корректность инфраструктуры на одном тесте и зафиксировать найденные несовместимости отдельно.

## Не входит в задачу

- Полное переключение всех тестов с SQLite на PostgreSQL.
- Исправление всех несовместимых миграций и тестов.
- Настройка CI и параллельного запуска.
- Изменение production-конфигурации или production-данных.
