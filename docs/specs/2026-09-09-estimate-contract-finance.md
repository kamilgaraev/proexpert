# Договорные цены и плановая маржа смет МОСТ

Статус: реализация в task-ветках, без публикации в production.

## Назначение и границы

Плановый договорной расчёт сравнивает доход заказчика с договорными расходами и собственными затратами. Исходная сметная стоимость служит лимитом и базой пропорционального распределения. Она не подставляется вместо отсутствующего дохода. Оплаты, фактическое выполнение, склад и акты не изменяются финансовым сохранением.

## Данные и совместимость

`estimate_finance_allocations` хранит независимые согласованные объёмы, цены, суммы, валюту, ставку и базу НДС, источник затрат, подтверждение состава и снимок исходной позиции. Денежные и количественные значения API передаются десятичными строками. Расчёты выполняются Brick Math.

Существующие `contract_estimate_items` сохраняют идентификаторы. Несколько финансовых распределений одного договора агрегируются в прежнюю связь. При снятии финансового распределения связь обнуляется, сохраняя идентификатор; явное отсоединение остаётся отдельным действием. Повторная синхронизация не переоценивает существующие связи. Неизвестная налоговая база старых сумм остаётся неизвестной, исходные суммы сохраняются отдельно.

Дочерняя позиция и зеркальный ресурс норматива связываются через `represented_by_item_id`. Новые нормативные позиции получают связь при создании. Старые неоднозначные представления пользователь отмечает как самостоятельный ресурс или выбирает соответствующую дочернюю позицию; проверяются родитель, единица и объём. Распределять зеркальный ресурс второй раз нельзя. Сначала нужно разрешить существующие распределения, если пользователь меняет представление ресурса.

Внутренние ресурсы из прежних JSON-расчётов показываются для проверки. Их подготовка к распределению выполняется явным сохранением. Неизвестные количественные и ценовые исходные значения не восстанавливаются предположениями. Последующие изменения исходного JSON отмечаются как расхождение.

## API

Все пути относительно `/api/v1/admin/projects/{project}/estimates`:

| Метод и путь | Назначение |
| --- | --- |
| GET `/finance` | Сводная проекта, все сметы, отдельные итоги по валютам |
| GET `/finance/export` | Excel проекта |
| GET `/{estimate}/finance` | Строки, ресурсы, разделы, договоры и серверные итоги всей сметы |
| GET `/{estimate}/finance/items/{item}` | Детализация позиции с родительской работой и ресурсами |
| POST `/{estimate}/finance/preview` | Пропорциональное распределение суммы либо предпросмотр цены из сметы |
| PUT `/{estimate}/finance` | Атомарная замена распределений выбранных целей |
| GET `/{estimate}/finance/export` | Excel сметы с детализацией |

`basis`: `with_vat` по умолчанию, либо `without_vat`. Сохранение принимает `revision`, UUID `mutation_id`, `target_keys` (`i:<id>`, `r:<id>`), все `lines` выбранных целей. Максимум 1000 целей и 5000 распределений за операцию. `expected_total` сверяется только с `total_line_keys`: строки одного договора либо собственных сил, одной валюты и налоговой базы. Нулевая база пропорций требует ручных сумм. Остаток копеек распределяется по наибольшим остаткам, при равенстве — по стабильному ключу строки.

`preview_operation=estimate_prices` переносит исходную цену только для строк с `adopt_estimate_price=true`. До сохранения серверные данные не меняются. Обычное сохранение не сбрасывает обнаруженное расхождение со сметой.

Изменение закупки ресурса требует включения родительской работы в операцию и явного `confirm_resource_changes`. Цена подрядчика автоматически не уменьшается. `resource_mappings` задаёт представление ресурсов, `prepare_resource_items` подготавливает старую внутреннюю детализацию.

## Полнота и защита

Объёмы дохода и исполнения проверяются независимо. Исполнители и собственная бригада совместно расходуют объём стороны затрат. Ресурсы по умолчанию входят в цену работы; выделенные закупки добавляются к затратам работы, доход повторно не начисляется.

Маржа показывается только для полностью оценённой позиции. При нулевом доходе процент отсутствует. Неполные строки сохраняют известные суммы; сводные показывают маржу оценённых позиций и количество неоценённых. Валюты не конвертируются и не суммируются между собой. Сметный лимит обозначен отдельно в рублях.

Права `budget-estimates.finance.view` и `.edit` независимы. Сервис проверяет организацию, проект и доступ пользователя, включая экспорт. Руководителю проекта и финансовому администратору доступны просмотр и изменение, бухгалтеру — просмотр. Существующие роли с соответствующими wildcard-правами сохраняют доступ.

Сохранение блокирует смету и позиции в транзакции, проверяет редакцию и записывает результат идемпотентной операции вместе с изменениями. Изменения исходных позиций, ресурсов и договорных связей повышают редакцию. Удаление/замена связанных позиций, изменение единицы и перенос между сметами блокируются до явного разрешения связей. Восстановление структуры версии с существующими связями также требует их разрешения.

## Интерфейс и экспорт

В карточке и конструкторе обычная таблица сохраняет колонки и получает значок связей. Обе версии конструктора используют общий компонент позиции. Режим «Доходы и расходы» сохраняет разделы, поиск по всей загруженной финансовой выборке и виртуализацию. Выбор ресурса открывает семейство работы для совместной проверки цены. Финансовая панель не запускает редактирование фактического выполнения.

Сводка проекта раскрывается в списке смет. Excel содержит сводную, позиции, распределения и разделы из тех же серверных расчётов, с выбранной базой НДС и признаками неполноты. Текстовые значения записываются безопасно от формул; денежные значения с безопасной для Excel точностью остаются числовыми, более длинные значения сохраняются текстом без потери точности.

## Проверка

Целевые сценарии: миллион/800 тысяч; 60/40 и превышение; копейки и нулевая база; разные ставки НДС; неизвестная база; собственная бригада; отдельная закупка и зеркальный ресурс; сохранность прежних сумм и связей; расхождения после изменения сметы; совпадение раздела/сметы/проекта/Excel; права и другой tenant; повтор запроса; конкурентное сохранение двумя процессами; неизменность выполненных работ и актов.

DB-тесты запускаются только каноническим `tests/Runtime/run-postgres-tests.ps1` с PostgreSQL 16 на 127.0.0.1:55433. Статические проверки: PHPStan, PHP syntax, TypeScript, ESLint. UI: целевые Vitest с MSW, браузерная проверка реальных компонентов на тестовых ответах API.

- Проверены 21 сценарий финансового расчёта и 5 сценариев совместимости с договорами и журналами. После исправления тестового сравнения сохранённых значений и обновления отдельной схемы журнала затронутые сценарии повторены точечно. Проверка конкуренции использует два PHP-процесса и настоящую блокировку PostgreSQL.
- PHPStan для новых сервисов, API, моделей и изменённых служб совместимости — без ошибок; последние изменения расчёта и экспорта проверены повторно. Синтаксис 24 затронутых PHP-файлов проверен.
