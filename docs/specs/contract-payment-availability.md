# Доступная сумма оплаты по договору

## Проблема

Форма создания счёта рассчитывала доступную сумму на клиенте только по утверждённым актам. Сервер для договоров поставки использует стоимость оприходованных поставок, поэтому UI мог разрешать сумму, которую API затем отклонял.

## API-контракт

`GET /api/v1/admin/payments/contracts/{contract}/availability`

Необязательный параметр: `project_id` для мультипроектного договора.

Ответ `AdminResponse.data`:

- `contract_id` — идентификатор договора;
- `basis` — `procurement_receipts` или `approved_acts`;
- `performed_amount` — каноническая сумма принятого исполнения;
- `committed_amount` — сумма действующих неавансовых и нефинальных платёжных документов;
- `available_amount` — неотрицательный остаток, доступный для обычного платежа.

Расчёт выполняется тем же доменным сервисом, который валидирует создание и отправку платёжного документа. Клиент не воспроизводит бизнес-правила выбора источника.

## Доступ и ошибки

- требуется право просмотра счетов;
- договор должен быть доступен текущей организации и, если указан, проекту;
- недоступный договор возвращает 404 без раскрытия чужих данных.

## Проверки

- договор поставки с оприходованием использует сумму поставок;
- обычный договор использует утверждённые акты;
- учтены уже созданные обычные платежи;
- UI показывает источник расчёта и ограничивает сумму по ответу API.
