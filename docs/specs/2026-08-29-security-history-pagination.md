# Пагинация истории безопасности

## Проблема

Административный API возвращает только последние 100 событий безопасности без метаданных. Интерфейс называет список историей входов, поэтому более старые события становятся недоступны без явного признака усечения.

## Контракт

- `GET /api/v1/admin/security/events` принимает `page` и `per_page`.
- `per_page` по умолчанию равен 20 и ограничен диапазоном 1–100.
- Ответ использует стандартный `AdminResponse::paginated`: массив событий в `data`, метаданные `current_page`, `per_page`, `last_page`, `total` в `meta`.
- Сортировка стабильна: сначала новые события, затем больший внутренний идентификатор.
- События доступны только текущему аутентифицированному пользователю; границы авторизации не меняются.

## UI-состояния

- Первая страница загружается вместе с данными безопасности.
- Следующие страницы добавляются по кнопке «Показать ещё».
- Обновление начинает загрузку с первой страницы.
- Известные признаки риска отображаются человекочитаемо; технические ключи не выводятся.

## Проверки

- Backend: две страницы, корректный порядок и метаданные; отклонение некорректного `per_page`.
- Frontend: параметры первой страницы, добавление следующей страницы, подписи всех признаков риска.
