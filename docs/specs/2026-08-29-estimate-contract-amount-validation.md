# Проверка суммы при привязке сметы к договору

## Контекст

До создания связи endpoint проверки суммы рассматривает только уже сохранённые покрытия. Поэтому передаваемый `contract_id` отсутствующего покрытия возвращает `is_valid=true`, `contract_total=null` и сообщение «Смета не покрыта договором». Пользователь может связать смету на сумму, многократно превышающую сумму договора, не получив предупреждения.

Статус `full_link` описывает полноту привязки позиций, а не финансовое соответствие. Он сохраняется как отдельный инвариант и не должен подменять денежную проверку.

## Целевой контракт API

- `GET /api/v1/admin/projects/{project}/estimates/{estimate}/contract/validation?contract_id={contract}` проверяет указанный договор текущей организации и проекта, даже если связь ещё не создана.
- `estimate_total` — сумма сметы без НДС.
- `covered_amount` — сумма позиций, которая будет связана с выбранным договором; для новой полной привязки это сумма сметы с учётом `include_vat`, когда параметр включён.
- `contract_total` — сумма выбранного договора.
- `difference` и `difference_percentage` рассчитываются по выбранному договору.
- `is_valid` остаётся advisory-признаком допуска ±5% и не запрещает осознанную привязку: разные договорные модели могут намеренно иметь отличие.
- Чужой договор, договор другого проекта или отсутствующий договор не раскрывается и даёт 404/422 по действующему стандартизированному контракту.

## UI-состояния

- После выбора договора и изменения флага НДС выполняется серверная проверка.
- Пока идёт проверка, кнопка привязки недоступна.
- При соответствии показывается подтверждение с суммами.
- При расхождении показывается заметное предупреждение с суммой сметы, суммой договора и отклонением.
- Значительное расхождение не блокируется молча: кнопка требует явного второго шага подтверждения в самом диалоге.
- Ошибка проверки блокирует привязку, чтобы пользователь не продолжал без финансового контекста.

## Проверки

- Backend PostgreSQL/HTTP-регрессия: кандидат без существующей связи возвращает реальные суммы и `is_valid=false` при отклонении более 5%; tenant/project scope сохраняется.
- Frontend Vitest: диалог вызывает проверку выбранного договора, показывает предупреждение, блокирует первый submit до явного подтверждения и передаёт `include_vat`.
- TypeScript, ESLint изменённых файлов, PHPStan изменённых PHP-файлов, Pint и `git diff --check`.

## Риски

- `full_link` нельзя переименовывать или менять семантику в этой задаче: он используется журналом работ и актированием как позиционное покрытие.
- Нельзя жёстко запрещать расхождение без отдельного доменного решения: договор может покрывать часть цены, содержать лимит или иметь отличающуюся налоговую базу.
- Проверка должна выполняться на сервере и не полагаться на суммы из списка договоров в браузере.
