# МОСТ: протокол серверной приёмки ПИР и BIM

Статус: **не выполнен**. Протокол подготовлен для проверки на сервере по решению пользователя. Он не подтверждает готовность production и не разрешает развёртывание, применение миграций, перезапуск рабочих процессов или изменение CI/CD.

Реализация и история проверок: [спецификация](2026-09-09-pir-platform-implementation.md), [матрица приёмки](2026-09-12-pir-acceptance-status.md). Не заменять полный план этим протоколом: локальные API/DB-регрессии остаются отдельными проверками.

## 1. Паспорт прогона

Перед началом заполнить значения; неизвестные параметры оставить явно неизвестными.

| Поле | Значение |
| --- | --- |
| Дата, исполнитель, серверный тестовый контур | |
| Commit backend, админки и конвертера | |
| Организация и тестовый проект | |
| Версии PHP, Node, Redis, Reverb, браузеров | |
| CPU/RAM серверных процессов и лимиты конвертера | |
| CPU/RAM/GPU и браузер каждого клиентского компьютера | |
| Сеть: расположение клиентов, тип подключения, обычная задержка | |
| Три IFC: имя, дисциплина, байты, SHA-256, редакция, число элементов | |
| Источник эталонных координат, единиц и контрольных свойств | |
| ID редакции набора и совместного сеанса | |
| Начало и конец 30-минутной части | |

Использовать три модели разных дисциплин **одного проекта**, имеющие известные точки совмещения. Три произвольных IFC не доказывают корректность общей системы координат.

Подготовить десять разных пользователей с доступом к проекту и просмотру всех трёх моделей. Использовать независимые авторизованные браузерные сессии. Несколько вкладок одного аккаунта не заменяют десять участников. Если все браузеры работают на одном компьютере, отметить это как ограничение, включая конкуренцию за память/GPU и фоновые вкладки.

Отдельно подготовить пользователей без права просмотра модели, без доступа к этому проекту и из другой организации. Для проверки состава нужны раздельные права редактирования и утверждения; для замечаний — права исполнителя, принимающего и управления блокировкой выпуска.

## 2. Готовность существующей инфраструктуры

Проверить фактические настройки штатным доступным способом, не менять их автоматически:

- приложение использует существующие S3/FileService, Redis и Reverb;
- IFC-задания обрабатываются через подключение `redis_ifc`, очередь по умолчанию `ifc-processing`;
- таймаут конвертера меньше таймаута задания, а `retry_after` больше обоих;
- текущие значения по умолчанию в коде: `DESIGN_VIEWER_CONVERTER_TIMEOUT=6600`, `DESIGN_VIEWER_JOB_TIMEOUT=6900`, `IFC_REDIS_QUEUE_RETRY_AFTER=7200`; записать реальные значения и ограничения процесса worker, а не считать defaults настройками сервера;
- остальные очереди не перенастроены ради IFC;
- доступен журнал обработки с этапом, временем, размерами и причиной ошибки; можно сопоставить обработку с конкретной редакцией;
- браузер устанавливает авторизованное WebSocket-соединение, а сервер разрешает вход именно в выбранный сеанс.

Отсутствие worker, диагностики или измерительных данных — незавершённая проверка, а не основание объявить приложение неисправным или запустить дополнительные серверы.

## 3. Пользовательские сценарии до нагрузки

Для каждой строки сохранить фактический результат и ID затронутых записей.

| Сценарий | Действия | Ожидаемый результат |
| --- | --- | --- |
| Состав ПД | Выбрать два раздела и собственный документ; посмотреть состав; создать комплект | Сохранены ровно показанные позиции и документы; прочие разделы не появились |
| Состав РД | Выбрать одну марку и несколько документов/групп; создать комплект | Одна марка, показанный состав; стадия и шифр не меняют состав скрыто |
| Права и ревизии | Редактор изменяет состав; другой пользователь утверждает; две вкладки пытаются сохранить одну исходную ревизию | Право утверждения отделено; устаревшее сохранение отвергнуто без потери принятого изменения |
| Повторный нормоконтроль | Проверить комплектность, затем изменить документ или блокирующее замечание и запросить выпуск | Старый результат не позволяет выпустить изменившийся комплект; сервер проверяет актуальное состояние |
| Продолжение загрузки | Начать multipart, дождаться нескольких частей, прервать сеть, повторно выбрать тот же файл | Учитываются принятые части; передаются отсутствующие; другой файл не продолжает прежнюю сессию |
| Повтор завершения | Повторить запрос завершения той же загрузки | Одна редакция файла, без дублирующей версии |
| Некорректный IFC | Передать повреждённый тестовый файл | Передача файла и результат разбора различаются; понятная ошибка, без вечной подготовки |
| Защищённые файлы | Получить ссылку разрешённым пользователем; проверить отказ в получении ссылки другим пользователем и истечение срока ссылки | Нет постоянного публичного адреса; защищённый маршрут совместимости проверяет доступ. Действующая подписанная ссылка сама является временным доступом — отсутствие JWT при её скачивании не считается ошибкой |
| Совмещение | Открыть три модели, сверить единицы и контрольные точки | Сохраняются общие координаты; модели не центрируются независимо |
| Явная поправка | Сохранить смещение/поворот для модели с недостаточными координатами; повторно открыть редакцию набора | Поправка воспроизводится; исходное преобразование не утрачено |
| Свойства | Выбрать известные элементы каждой модели, сравнить GlobalId, категорию, единицы и свойства с эталоном | Идентичность относится к конкретной редакции; материалы/объёмы показываются только при наличии |
| Исторический набор | Открыть набор, загрузить новую IFC-редакцию, продолжить старый сеанс | Старый сеанс остаётся на прежних редакциях; новый состав набора создаётся явно |
| Полный экран | Войти/выйти из полного экрана, затем использовать Escape | Геометрия, выбранный элемент и контекст сеанса сохраняются; новый просмотрщик не создаётся вместо старого |

## 4. Тридцать минут совместной работы

Отсчёт начинается после входа всех десяти участников. На протяжении прогона доступны три модели; фиксировать отключение модели и пользователя, а не скрывать его из результатов.

| Интервал | Действия |
| --- | --- |
| 00–05 мин | Все входят в один сеанс; сверяют участников и редакцию набора; каждый включает/выключает видимость моделей и просматривает свойства |
| 05–10 мин | Участники перемещают курсоры и выбирают элементы разных моделей; несколько раз снимают выделение. Проверить, что чужой выбор не подменяет локальный |
| 10–15 мин | Несколько участников добровольно следуют за одним ведущим. Один вручную двигает камеру, затем ведущий выходит. Следование прекращается в обоих случаях |
| 15–20 мин | У двух клиентов временно обрывается WebSocket. Остальные продолжают просмотр. После восстановления обновляются участники и постоянные данные; старое движение не проигрывается |
| 20–25 мин | Разные пользователи создают замечания с элементом/точкой, камерой и снимком. Исполнитель передаёт исправление на проверку, принимающий возвращает или принимает его |
| 25–30 мин | Повторно открыть созданные замечания и исходные редакции. Проверить номера, ответственных, снимки, статусы и историю; сверить отсутствие потерянных или повторных записей |

Дополнительно проверить независимый просмотр при недоступном WebSocket: уже доступная геометрия и локальное управление работают; совместные функции явно недоступны. Это не обещание работы сетевых операций без сети.

## 5. Измерения

Записать отдельно:

- время от открытия набора до возможности управлять всеми тремя моделями, для холодного и повторного открытия;
- память клиента до открытия, после загрузки, в середине и в конце прогона;
- наблюдаемую плавность и длинные зависания на указанных компьютерах;
- длительность и пиковую память подготовки каждой модели, размеры IFC, геометрии и индекса элементов;
- число отправленных/полученных совместных событий, разрывы связи и количество постоянных замечаний до/после прогона.

Для p95 доставки событий нужен журнал сопоставленных отправок и приёмов. Метод сопоставления не должен менять разрешённую структуру transient-сообщений. При измерении между компьютерами записать способ синхронизации часов и погрешность. Половина RTT, задержка ping и субъективная оценка курсора не являются измерением односторонней доставки.

Из сопоставленных событий вычислить задержки и 95-й процентиль, указав число наблюдений, типы событий и погрешность. Потери учитывать отдельно; не удалять медленные события как «выбросы». Критерий плана: **p95 ≤ 500 мс в описанной тестовой сети**. Если данных для сопоставления или синхронизации часов нет, отметить показатель как непроверенный. Прежний короткий localhost-прогон Reverb не подставлять вместо него.

Общий критерий 30-минутной части: нет потери замечаний, падений и дублирования обработки. Не обещать работу IFC произвольного размера по результатам этих трёх файлов.

## 6. Замечания, подписки и строительные связи

Повторить доступ к одной проектной записи при сочетаниях «ПИР», «качество», «оба», «ни одного», а также без прав и с чужим проектом. При двух модулях проверить одинаковый ID. Через ПИР нельзя открыть строительное замечание только потому, что известен его номер.

Проверить снимок после истечения временной ссылки и повторного открытия карточки. Новая IFC-редакция не закрывает замечание. Снятие блокировки выпуска требует отдельного права и основания; закрытие нового замечания означает принятие исправления.

Для каждого из шести объектов — позиция сметы, задача графика, запись журнала, выполненная работа, заявка на закупку, исполнительный документ — выполнить один полный цикл:

1. Сохранить исходные суммы, количества, статус и ссылку на объект.
2. Связать его с конкретной редакцией документа либо элементом модели.
3. Открыть источник из строительной карточки; проверить именно связанную редакцию и лист/элемент, включая историческую редакцию.
4. Выпустить новую редакцию и проверить появление проверки влияния.
5. Выполнить решение «оставить старую», «перенести» или «завершить» с основанием. Распределить решения по объектам так, чтобы встретились все три варианта.
6. В двух вкладках попробовать принять разные решения по одной ревизии связи: одно сохраняется, второе получает конфликт.
7. Сверить сохранение прежней истории, сумм, объёмов и фактов выполнения. Автоматического пересчёта быть не должно.

После отключения ПИР проверить доступные по правам строительные карточки и сохранённую историю; новое открытие моделей и действия ПИР закрыты. Отключение подписки не может физически удалить ранее загруженные байты из памяти браузера; проверять новые запросы и поведение интерфейса отдельно.

## 7. Управляемые сбои обработки

Эта часть выполняется только в отдельном согласованном тестовом окружении оператором инфраструктуры. Команд остановки worker или изменения общей очереди здесь нет.

| Сбой | Что подтвердить |
| --- | --- |
| Ошибка конвертера | Ошибка привязана к редакции и этапу; можно отличить её от успешной загрузки файла |
| Обрыв обработки | Обработка обнаруживается как зависшая и восстанавливается по предусмотренному процессу; нет вечного статуса |
| Повтор задания/одновременная подготовка | Для редакции не возникает двух независимых результатов и конкурирующих финализаций |
| Отмена и истечение multipart-сессии | Завершённый файл не повреждается; незавершённые части очищаются предусмотренным процессом |
| Отказ хранилища | Ошибка видна пользователю; повтор не создаёт дубликат версии или замечания |
