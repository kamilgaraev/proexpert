# Пустые источники отчётов

## Проблема

Readiness-проверки отчётов должны отличать корректный пустой срез от неполного источника. Сейчас отчёт надёжности поставок требует watermark backfill даже при нулевом наборе строк, а общая ошибка readiness выходит как необработанная внутренняя ошибка. Это запускает повторные попытки и оставляет UI в состоянии материализации.

## Контракт

- Нулевой eligible-набор является готовым источником с нулевыми счётчиками качества.
- Все readiness-проверки на `SourceReadinessResult` используют один и тот же empty-result контракт.
- Непустой источник по-прежнему обязан пройти проверки полноты, версий, hash и backfill.
- Нарушение readiness возвращается как `REPORT_SOURCE_UNAVAILABLE`, а не `REPORT_INTERNAL_ERROR`.
- Материализаторы получают возможность сформировать канонический пустой snapshot и завершить запуск со статусом `ready`.

## Проверки

- Unit-тест общего empty-result и типизированной ошибки неполного источника.
- Контрактный тест раннего выхода для всех четырёх readiness-проверок.
- Целевые тесты readiness и job-классификации ошибок.
