# Инвентаризация старых привязок

Команда `estimates:finance-inventory` предназначена для оператора выпуска. Она только читает данные и выводит JSON Lines: одна строка на страницу, до 500 привязок. HTTP-маршрута у команды нет. Запуск на рабочей локальной БД запрещён правилами проекта; проверки выполняются через канонический PostgreSQL launcher. На production применяются правила штатного выпуска и read-only диагностики.

Параметры:

- `--organization_id=<ID>` ограничивает отчёт организацией сметы. Без параметра проверяются все организации, включая связи с отсутствующей сметой.
- `--after=<ID>` продолжает чтение после указанного идентификатора старой связи.

Для каждой связи сохраняются исходные идентификаторы, объём, суммы, примечание и временные метки в `preserved`. Денежные значения остаются десятичными строками. `preserved_values_hash` позволяет сравнить эти поля до и после переноса. Отдельно выводятся признак нового управления связью, идентификаторы и ключи финансовых условий, исключение позиции и диагностические несоответствия области данных.

Отчёт не вычисляет подтверждённую маржу и не восстанавливает неизвестный НДС. Для предпросмотра финансового переноса используется существующий `finance/preview` с `preview_operation=migration_plan`; в интерфейсе доступна выгрузка всех страниц сметы в CSV. Применение выполняется существующим `finance/save` с `operation=migration_apply`, версией сметы, идентификатором операции и хешами исходных связей.

Сверка выполняется по `legacy_link_id`: множества старых идентификаторов и `preserved_values_hash` должны совпадать до и после переноса; появление финансовых ключей ожидаемо. Отсутствующие и новые связи, изменившиеся хеши и непустые `issues` требуют разбора. Одного совпадения общей суммы недостаточно.

Постраничный отчёт не является атомарным снимком всей БД. Изменения пользователей между чтениями нужно отличать от последствий переноса по истории условий и времени операций. Сам перенос повторно проверяет версию и хеш исходных данных; отчёт не заменяет эти проверки. Сохранность утверждённых актов, оплат и сумм договоров проверяется отдельно, поскольку их содержимое не входит в этот инвентаризационный хеш.
