# Общая разметка чертежей ПИР

Каждый завершённый штрих автоматически сохраняется без текста замечания. Общие рисунки принадлежат конкретной версии документа и странице; сервер назначает автора и время. Замечания проекта остаются отдельным процессом. Старая разметка в замечаниях продолжает отображаться.

Админка и мобильное приложение используют document-versions/{versionId}/drawing-strokes: GET получает изменения после after_revision, POST принимает client_id UUID и annotations существующей схемы с одним штрихом, DELETE по client_id отменяет только собственный штрих. Чтение требует documents.view, запись — review в строгой области проекта; сервис проверяет организацию, проект и всю цепочку родителей версии. Автор не принимается от клиента.

Хранилище: отдельные записи штрихов с JSONB, UUID, автором, временем и tombstone удаления. Счётчик изменений версии обновляется под блокировкой версии в той же транзакции, без изменения даты исходного документа и актуальности нормоконтроля. Повтор UUID с тем же содержимым возвращает запись, с другим содержимым или автором — конфликт. Отмена до запоздавшего POST резервирует UUID удалённой записью, поэтому поздняя отправка не возвращает рисунок. Ответ GET: items, revision, has_more, can_annotate; до 200 изменений за запрос. Клиенты применяют дельты по UUID и ревизии, дочитывают страницы, затем обновляются каждые 5 секунд при активном просмотре. Общий курсор продвигается только после GET, а не после собственного POST/DELETE. Инструменты записи доступны после подтверждения права сервером.

Сохранение и ошибки видны на экране. Повторы используют тот же UUID. Незавершённые отправки сохраняются в памяти открытого просмотрщика и защищены предупреждением при закрытии; работа без сети после полного закрытия приложения в эту поставку не входит. Отмена своего штриха проходит через тот же серверный механизм и видна другим участникам. Чужие рисунки доступны для просмотра, без редактирования. Панель показывает автора, время и число штрихов на листе.

Проверки: изоляция организаций и проектов, запрет чужого удаления, права, формат/страница/ограничения штрихов, повтор POST, дельты и tombstones; очередь сохранений и поздние ответы; админка и мобильный клиент читают одну запись. Backend выпускается до клиентов. Production — только после merge в main.
