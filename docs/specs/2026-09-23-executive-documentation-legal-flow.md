# ИД объекта: регистрация, перечень и внутренняя проверка

Основание: [приказ Минстроя № 344/пр, приложение № 1 и приложение № 2](https://legalacts.ru/doc/prikaz-minstroja-rossii-ot-16052023-n-344pr-ob-utverzhdenii/) в редакции от 23.06.2025, [постановление Правительства № 468, пункт 7](https://base.garant.ru/12176727/), [СП 48.13330.2019](https://protect.gost.ru/sp/details/278f4ffa-b29b-4733-b8ac-d9a5ff3775cc). Применимость отдельного вида к объекту определяется утверждённым для него перечнем, проектной и рабочей документацией, договором. Наличие профиля в МОСТ само по себе не делает его обязательным для любого объекта.

## Сценарий

1. Пользователь с правом внутреннего подтверждения прикладывает уже утверждённый вне МОСТ перечень объекта: файл, утверждающая сторона, дата, пункты. Новая загрузка создаёт следующую неизменяемую редакцию с SHA-256. Система предлагает пункты по существующим документам и работам, ответственный сверяет их с файлом.
2. Для черновика комплекта выбирают относящиеся к нему пункты этой редакции. Для шаблонных актов при сверке отдельно отмечают, предусмотрены ли авторский надзор и отдельный исполнитель. Требования ИД получают ссылку на редакцию. При её смене совпадающие по виду, ключу и области доказательства сохраняются; переданный комплект не меняется.
3. Основное действие — загрузить готовый документ. Обязательны вид и файл либо паспорт складского прихода. Название предлагается по имени файла. Дата, работа и дополнительные связи указываются при наличии. Переписывать текст и подписантов из документа не требуется. Пакетная загрузка использует то же правило.
4. Паспорт складского прихода копируется в неизменяемую редакцию ИД. Остаётся ссылка на приход, исходный файл и его SHA-256. Приход другого объекта или организации недоступен. Паспорт изготовителя служит исходным документом о качестве и не закрывает сам по себе пункт о проведённом входном контроле.
5. Исправление создаёт новую редакцию. Для файла хранится признак «копия», «скан бумажного документа» или «электронный оригинал»; отдельный файл подписи и его SHA-256 могут храниться вместе с электронным файлом. МОСТ не выполняет юридическую проверку сертификата и подписи, поэтому этот признак отражает заявление загрузившего пользователя.
6. Передача требует совпадения с перечнем, актуальной редакции, наличия файла, правильного объекта, доказательств по пунктам и внутреннего подтверждения. Количество бумажных оригиналов вводится при передаче. Манифест фиксирует перечень, версии и количество экземпляров. Старые переданные комплекты не пересчитываются.

Внутренние статусы «на проверке», «проверен в МОСТ» и «передан в МОСТ» фиксируют действия пользователей системы. Они не заменяют подписание исполнительной документации по пунктам 3–5 приложения № 2 к приказу № 344/пр. Пять форм актов из приложений 1–5 остаются отдельными шаблонами составления; для них нужны реквизиты, указанные в форме.
