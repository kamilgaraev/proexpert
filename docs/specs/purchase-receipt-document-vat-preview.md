# Предпросмотр накладной при приемке заказа

## Проблема

Форма приемки заказа собирала ТОРГ-12 на клиенте и считала каждую строку без НДС. Для заказа с НДС, включенным в цену, это приводило к юридически неверным суммам: стоимость без НДС совпадала с полной стоимостью, а НДС был равен нулю.

## Контракт

- `POST /api/v1/admin/procurement/purchase-orders/{id}/receipt-document/preview` принимает тот же состав приемки, что и формирование PDF, кроме ключа идемпотентности.
- Маршрут требует право `procurement.purchase_orders.receive` и ограничивает заказ и склад текущей организацией.
- Предпросмотр проверяет статус заказа, оплату, склад и строки приемки, но не создает приход и не меняет остатки.
- Ответ содержит каноническую модель ТОРГ-12, которую интерфейс показывает без повторного расчета денежных значений.

## Расчет НДС

Источник режима и ставки НДС — коммерческий снимок заказа. Если снимка нет, допускается переход к принятому предложению поставщика; отсутствие обоих источников означает, что НДС не применяется.

- `included`: цена строки содержит НДС; сумма без НДС уменьшается на рассчитанный НДС, итог равен введенной сумме строки.
- `excluded`: цена строки не содержит НДС; НДС добавляется к итогу строки.
- `not_applicable`: НДС равен нулю, ставка в документе отсутствует.

Расчет использует тот же доменный калькулятор, что и коммерческое предложение. Доставка не входит в товарные строки ТОРГ-12.

## Состояния интерфейса

- При переходе к накладной интерфейс запрашивает серверный предпросмотр и показывает индикатор загрузки.
- При ошибке переход блокируется; стандартизированное сообщение API не дублируется локальным уведомлением.
- Если в организации нет склада, интерфейс объясняет причину и дает переход в раздел складов.
- Успешное оприходование показывает только сообщение общего API-слоя.

## Проверка

- Интеграционный backend-тест проверяет включенный НДС 20%: `1800 = 1500 + 300`, при этом предпросмотр не создает приход.
- Тест интерфейса проверяет запрос предпросмотра, отображение серверных сумм и отсутствие повторного уведомления после приемки.
- Тест API-клиента фиксирует маршрут и тело запроса.
