# Завершённый жизненный цикл запроса поставщику

## Наблюдение

После принятия КП и создания заказа запрос поставщику остаётся в сохранённом статусе `responded`. Текущий расчёт жизненного цикла смотрит только на решение `selected` и продолжает предлагать `accept_proposal`, хотя выбранное КП уже имеет статус `accepted` и связано с заказом.

## Контракт

- Сохранённый статус запроса поставщику не меняется: он описывает получение ответа.
- Расчётный `workflow_summary` учитывает более позднее состояние выбранного КП.
- Если среди КП запроса есть принятое, итоговая стадия запроса совпадает с жизненным циклом принятого КП.
- При наличии созданного заказа действие отсутствует; для допустимой старой записи без заказа сохраняется штатное действие создания заказа.
- Решение, права и транзакции принятия КП не изменяются.

## Проверка

- PostgreSQL-регрессия для цепочки `responded → selected → accepted → purchase order`.
- Существующие тесты `ProcurementLifecycleServiceTest`.
- PHPStan изменённого сервиса и синтаксическая проверка.
- После деплоя production-запрос поставщику не должен предлагать повторное принятие КП.
