# Сверка графика платежей с фактическим реестром

## Проблема

После регистрации или возврата платежа суммы и статус платежного документа меняются, но строки его графика остаются в прежнем состоянии. В результате одна и та же сумма одновременно отображается как фактически оплаченная и как ожидающая оплаты.

## Инварианты

- Фактический реестр транзакций остаётся источником истины для общей оплаченной суммы документа.
- Оплаченная сумма документа распределяется по строкам графика детерминированно: по сроку, номеру платежа и идентификатору.
- Строка получает статус `paid`, только когда распределённая сумма полностью покрывает её сумму.
- Частично покрытая строка остаётся `pending`, но хранит точное `paid_amount`.
- Возврат пересчитывает распределение и при необходимости снова открывает ранее оплаченную строку.
- Сверка выполняется в той же транзакции и под блокировкой строк графика.
- Повтор идемпотентной команды не должен повторно увеличивать распределение.

## Контракт выдачи

API графика возвращает `paid_amount`, `paid_at` и `payment_transaction_id`, чтобы все клиенты могли показать фактическое состояние без самостоятельных вычислений.

## Проверки

- Полный первый платёж графика закрывает только первую строку.
- Возврат части платежа открывает первую строку и сохраняет частично распределённую сумму.
- Идентификатор платежного поручения присутствует в реестре транзакций.
