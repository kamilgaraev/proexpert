# Логистические единицы склада: owner UX

## Цель

Сделать реестр и форму логистических единиц понятными владельцу организации без раскрытия внутренних ключей API и без неоднозначного размещения по зоне и ячейке.

## Контракт API

- Создание и изменение принимают прежние поля без изменения транспортного контракта.
- Переданные обязательные поля `name`, `code`, `unit_type`, `status` не могут быть пустыми при частичном обновлении.
- Ошибки валидации используют русские названия бизнес-полей.
- Выбор ячейки остаётся ограничен текущими организацией и складом; несовпадение зоны и ячейки отклоняется существующей доменной проверкой.
- Изменение родительской единицы не может создать цикл: сервер проверяет всю цепочку родителей, а не только прямую ссылку на саму себя.

## Состояния интерфейса

- Фильтры зоны, типа, статуса и активности имеют доступные имена и работают независимо.
- Активность показана отдельно от операционного статуса в карточке и деталях.
- Пустой реестр предлагает создать первую единицу; пустой результат поиска или фильтрации объясняет, что совпадений нет, и позволяет сбросить условия.
- В форме все выпадающие поля имеют доступные имена.
- После выбора ячейки её зона выбирается автоматически; при выборе зоны список ячеек ограничивается этой зоной.
- При изменении вложенности текущая единица и все её потомки исключаются из списка возможных родителей.
- Вместимость и загрузка показываются в единицах содержимого, вес брутто — в килограммах, объём — в кубических метрах.
- В пользовательских действиях используется полное название «логистическая единица».

## Права

Новые права не вводятся. Владелец использует существующий доступ к складскому контуру; серверные границы организации и склада не ослабляются.

## Проверки

- Backend PostgreSQL-регрессия: русские ошибки создания и изменения, запрет циклической вложенности, сохранность исходной записи при 422.
- Frontend Vitest: доступные имена фильтров и формы, фильтр активности, заметность активности, контекстное пустое состояние, единицы измерения, согласование зоны с ячейкой и исключение потомков из списка родителей.
- TypeScript, ESLint, PHP syntax, Pint, PHPStan по изменённому PHP-коду, `git diff --check`.
- Production owner: отрицательные значения, создание, поиск, все фильтры, изменение, неактивное состояние, удаление с отменой и подтверждением.

## Риски

- Не смешивать операционный `status` с `is_active`.
- Не выводить числовые значения без единиц.
- Не подменять текущую модель загрузки подсчётом фактического содержимого: это отдельный будущий контракт.
- Не показывать ячейки другого склада или организации и не ослаблять серверную проверку размещения.
