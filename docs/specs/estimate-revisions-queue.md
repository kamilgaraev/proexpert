# Фоновое создание редакции сметы

Реализовано в task-ветке; выпуск в production отдельно не выполнялся.

POST `/api/v1/admin/estimates/{estimateId}/versions/revisions` принимает причину и заголовок `Idempotency-Key`, сохраняет операцию и возвращает AdminResponse с HTTP 202. Поле `data` содержит `id`, `estimate_id`, `status`, `message`, `error_code`, `created_at`, `finished_at`. Повтор завершённого запроса возвращает эту же операцию с HTTP 200. Конфликт с активной редакцией возвращает 409; недоступность постановки в очередь — 503 с безопасным сообщением. Ошибки прав и валидации сохраняют штатные статусы.

GET `/api/v1/admin/estimates/{estimateId}/versions/revisions/latest` возвращает последнюю операцию или null. Проверяются организация и право просмотра сметы. Причина редактирования и техническое исключение в статус не включаются.

Состояния: `queued` → `processing` → `completed` или `failed`. Уникальный индекс запрещает одновременно две активные операции одной сметы. Ключ запроса уникален в пределах сметы. Задание повторно проверяет доступ инициатора в сохранённой организации и неизменность утверждённой исходной версии. Смена текущей организации пользователем не переносит операцию в другую организацию.

Очередь `estimate-revisions`, соединение `redis_estimate_revisions`, выделенный обработчик Horizon. HTTP-лимит 30 секунд не изменён. Задание: 600 секунд; Horizon: 660 секунд; повторная доступность задания: 720 секунд. Изменение рабочей копии, снимок и завершение операции фиксируются одной транзакцией. Повторная доставка завершённого задания не меняет смету. Передача в Redis выполняется после сохранения операции; сведения об отправке записываются до публикации, чтобы HTTP-запрос не ждал блокировку строки работающим заданием.

Планировщик раз в минуту проверяет до 50 незавершённых операций старше 12 минут, пропуская заблокированные выполняющимся заданием строки. Потерянная доставка повторяется, не более трёх публикаций; далее операция получает ошибку `worker_unavailable`. После явного отказа пользователь запускает новую попытку с новым ключом. Код восстановления требует работающего штатного планировщика.

Канал `estimate_revisions` пишет ежедневные файлы `storage/logs/estimate-revisions-YYYY-MM-DD.log`, хранение 30 дней. События: постановка, начало, завершение, ошибка. Контекст: ID операции, сметы, организации, инициатора, код/класс исключения и расположение вызовов без аргументов. Тексты запросов, причина, пароли и SQL bindings не записываются. Терминальные сбои также остаются в таблице операций и стандартном журнале failed jobs.

Админка проверяет состояние при открытии страницы и каждые три секунды, пока операция активна. После сетевой ошибки проверка повторяется. После завершения обновляется история; после ошибки показывается номер задачи. Перезагрузка страницы не теряет состояние; поздний ответ другой сметы игнорируется.

Для выпуска требуются миграция таблицы операций, штатное применение новой конфигурации Horizon и одновременно совместимая админка. Команды production вручную не выполнялись.
