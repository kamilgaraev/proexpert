# Быстрое завершение отчётов без настроек организации

## Проблема

Запуск отчёта сохраняется атомарно вместе с outbox-intent и немедленно публикуется через
`ReportDispatchIntentPromptPublisher`. Плановый reconciler остаётся резервным механизмом.
Для отчёта надёжности поставок дальнейшее выполнение зависало в повторных попытках, когда
в выбранном срезе присутствовала хотя бы одна строка, но организация ещё не создала
версию политики.

## Контракт

- Пустой срез материализуется без политики и возвращает нулевые итоги.
- Непустой срез без настройки организации использует неизменяемую встроенную политику
  `supply-reliability-default.v1`.
- Явная версия политики организации всегда имеет приоритет.
- Встроенная политика входит в `source_hash`; снимок остаётся воспроизводимым.
- `policy_version_id` для встроенной политики равен `null`.
- Немедленная публикация задания остаётся best-effort; durable outbox и reconciler
  гарантируют восстановление при недоступности транспорта.

## Проверки

- Регрессионный тест на fallback непустого среза без политики.
- Полный набор unit-контрактов supply reporting.
- PHPStan и Pint для изменённых PHP-файлов.
- `APP_ENV=build php artisan package:discover` для проверки source-hash guard.
