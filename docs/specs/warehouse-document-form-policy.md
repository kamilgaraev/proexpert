# Политика складских первичных документов

## Назначение

API должен формировать только ту первичную форму, которая соответствует фактической складской операции. Доступ к экспорту определяется профильным складским правом, а не только наличием доступа к интерфейсу.

## Совместимость операций

- М-4 и М-7: поступление материала (`receipt`).
- М-11: внутреннее перемещение со склада либо внутренняя выдача на проект, ответственному или в производство.
- М-15: только передача подрядчику, отмеченная признаком `is_contractor_transfer`.
- Акт списания: утрата, порча, утилизация или корректировка по инвентаризации.
- М-17: карточка движения материала по выбранному складу.
- М-8: лимитно-заборная карта резерва.
- ИНВ-3: акт инвентаризации.

Несовместимая форма возвращает `422` с понятным сообщением. Отсутствующая или принадлежащая другой организации операция возвращает `404` без раскрытия её существования.

## Права

- М-4 и М-7: `warehouse.receipts`.
- М-11: `warehouse.manage_stock`.
- М-15: `warehouse.transfers`.
- М-17: `warehouse.reports`.
- М-8: `warehouse.advanced.reservations`.
- акт списания: `warehouse.write_offs`.
- ИНВ-3: `warehouse.inventory`.

## Пользовательские идентификаторы

Названия складов подрядчиков, причины движений и реквизиты М-15 используют имя подрядчика или организации. Внутренние ID остаются только машинными связями API и не включаются в видимые коды, описания и причины операций.

## Проверки

- PostgreSQL-регрессия совместимых и несовместимых операций.
- Проверка tenant scope и ответов `404`/`422`.
- Контракт middleware для каждого маршрута экспорта.
- Регрессия человекочитаемого склада подрядчика и метаданных М-15.
