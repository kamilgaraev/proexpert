# Работа со сметами

Три операции в админке одного проекта: актуализация отдельных смет, объединение в одну сводную и исходная смета плюс добавления минус исключения. Результаты всегда новые черновики; договоры и акты не переключаются. Для корректировки переоценка выключена по умолчанию.

Сервер хранит операцию, поколения предпросмотра, решения, отпечаток источников и строки происхождения. Предпросмотр и применение выполняются очередью. Подтверждённые акты защищают остаток исходных строк; добавления не увеличивают исключаемый остаток. Изменение исходных данных требует нового предпросмотра с очисткой решений.

Межсметное совпадение определяется типом, кодом/нормативом, единицей, разделом и условиями расчёта. Неоднозначные пары решает пользователь. При сохранении цен разные цены означают разные позиции. Индексация использует базисную цену выбранного норматива; отсутствующие источники требуют подтверждённой ручной цены. Прайсы XLSX/CSV импортируются с явным сопоставлением колонок, валютой, датой и НДС.

API: POST estimate-operations; GET estimate-operations/{id}; PATCH estimate-operations/{id}/resolutions; POST estimate-operations/{id}/apply с Idempotency-Key. Дополнительно GET estimate-operations/options и POST estimate-price-lists/inspect, POST estimate-price-lists. Все маршруты находятся в проектном Admin API. Право создания результата и доступ к каждому источнику проверяются сервисом.

Статусы: queued, processing, needs_resolution, ready, applying, completed, failed, stale. В интерфейсе сохраняется ID операции в URL. Строки предпросмотра выдаются по 50, доступен фильтр конфликтов. Из completed можно перейти к новым сметам; failed/stale позволяют обновить предпросмотр. Повтор применения одной операции не создаёт дополнительные сметы.

Приёмка: 100 + 20 − 30 = 90; при выполнении 80 из 100 исключение 30 запрещено даже с добавлением 20. Проверяются НДС, вложенные ресурсы, отсутствие двойного счёта актов/ресурсов, источники цен, конкурирующие изменения и права.

Пределы первой версии: 20 смет и 20 000 строк с учётом вложенных деталей на операцию; 10 прайсов. Прайс: 10 МБ, 20 000 позиций, XLSX после распаковки до 50 МБ. Используется уже расширенная в main точность: количества позиций — 8 знаков, цены — 4; количества ресурсов — 18, цены ресурсов — 12. Новая миграция создаёт только таблицы операций и прайсов, не сужает типы существующих данных. Суммы проверяются на границы decimal(15,2) до создания результата.

Цена работы в коммерческом прайсе и ручном подтверждении означает прямые затраты без НР и СП. Без явных новых ставок импортированные начисления сохраняют отношение к ФОТ; когда подтверждённого ФОТ нет — к прямым затратам. Новые ставки начисляются на прямые затраты по существующим правилам калькулятора. НДС результата задаётся отдельно. Старый региональный контекст при переоценке очищается, выбранный период и подтверждения записываются в происхождении операции. Базисные итоги пересчитываются только для подтверждённой базы; смешанные коммерческие цены не получают вымышленную базисную стоимость.

Фиксированные резервы включаемых исходных смет сохраняются отдельной суммой, показываются в предпросмотре и не начисляются повторно через позиции. Резерв исключающей сметы не вычитается. Дополнительные затраты остаются классификацией внутри цены.

Расчёты используют существующий redis_estimate_revisions / estimate-revisions с worker timeout 660 секунд и memory 512 МБ; timeout операции 600 секунд. Новые очереди, supervisor и настройки выпуска не добавляются.
