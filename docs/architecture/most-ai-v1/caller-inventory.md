## Семантика статуса и границы

`source-reachable` означает обнаруженную caller-chain, не telemetry production. `configurable` означает альтернативный DI/config route; фактический selected provider неизвестен. `DI-bound/dormant` не означает отсутствующий sink или доказанный обычный raw-PDF поток. `unknown` не означает безопасное отсутствие пути.

Transport ID T1–T7 соответствует историческому privacy inventory и сохраняется. Purpose keys в этом документе — проектные labels реестра, не зарегистрированные callable API имена. Они должны получить frozen version и owner decision в будущей LEAD-04/G0. Пакет 01 не начинает эту задачу.

App, worker, CLI и scheduler имеют одинаковую privacy-обязанность; обход UI или отсутствие видимого caller не исключают sink. У каждого будущего включённого purpose нужны actor/tenant/project/field scope, минимальная typed projection, source/profile versions, identity, category policy и fresh guard. Source ACL/лимиты/JSON schema сами по себе не дают разрешения на передачу provider.

## Target V1 и безопасное выключение

Включённый V1 путь передаёт только immutable exact bytes trusted Processor через authenticated integrity-protected канал единому Gateway. Gateway-only credentials и hard egress enforcement обязательны. Fresh ACL/consent/purpose/policy/source-generation check сериализуется с revoke и dispatch; каждый новый attempt/retry/loop проверяется заново. Budget guard не заменяет privacy guard; timeout с неизвестным provider outcome не оправдывает raw retry.

Любой sink/caller, который не имеет доказанного Required pipeline и approved purpose/vendor evidence, должен оставаться выключенным для соответствующего V1 scope. Это требование будущей реализации: документ не устанавливает runtime block. Unknown AIAnalyzer caller и conditional source-reachable T7 остаются в inventory и должны быть блокированы либо включены через тот же safe route. Динамический wrapper, пользовательский override endpoint, mutable artifact URL и provider redirect требуют явного negative evidence.

Separate Admission Authority, global dispatch nonce ledger и per-envelope cryptographic signature не возвращаются в V1 Required. Отложенные механизмы не разрешают cached approval, standalone SDK retry, forged SafeDTO или прямой egress.

## Acceptance и evidence gaps

Source inventory проверяется на pinned code: payload/modalities/default endpoint, retry/fallback/storage controls, caller/worker/CLI/scheduler roots и registry. Real runtime endpoint/model/config-cache, deployment-only cron, внешние wrappers, provider redirect/runtime behavior и workload network isolation не устанавливаются без отдельного разрешённого evidence. Пока эти gaps открыты, полное acceptance «dynamic wrappers и deployment-only cron проверены» не выполнено; inventory не закрыт и Ready for Merge=No.

Документальная полнота T1–T7 и сохранение proposed tools не доказывают gate readiness. Safe enabled/disabled feature scope, включая BIM readers/jobs/collectors и client context, требует будущих серверных gates и независимого QA. Все 18 capability gaps сохранены в LEAD-01 ledger; этот inventory не объявляет их готовыми.
