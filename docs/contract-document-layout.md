# Компоновка документа договора

Версия схемы `document.attrs.layout.version = 1`. `page` содержит `format` (A4/A5/Letter), `orientation` (portrait/landscape), поля `margins` (top/right/bottom/left, мм). `grid` содержит `size` (мм), независимые `visible` и `snap`.

Блочные узлы допускают `attrs.layout`: стабильный `id`, координаты `x/y`, `width`, `minHeight` в мм; необязательные `breakBefore`, `align`, `firstLineIndent`, `lineHeight`, `spaceAfter`. Координаты отсчитываются от печатной области; y продолжается между страницами. Высота — минимальная: содержимое увеличивает блок. Пересекающиеся по горизонтали нижние блоки сдвигаются; соседние колонки сохраняются.

Ненумерованный узел `group` сохраняет геометрию размещённой библиотечной вставки. Resolver раскрывает закреплённую версию blockReference в group, сохраняет clause.attrs.id и добавляет namespace к дочерним layout.id. Вложенные группы сохраняют относительную компоновку. Старые документы без layout используют прежний renderer/exporter.

Preview по-прежнему возвращает `html: string`. Для компоновки сервер измеряет текст DejaVu Sans и формирует общий план страниц для HTML/PDF/DOCX. HTML содержит канонические метаданные; exporter проверяет схему плана и точное совпадение HTML, отклоняет активные ссылки/изменённые стили. Длинные абзацы и ячейки делятся по строкам, текст остаётся текстом. DOCX использует плавающие текстовые блоки и встроенные шрифты. Допустимы до 501 страницы; слишком большой отдельный блок явно отклоняется, а не обрезается. Браузерный печатный диалог не является экспортом утверждённой редакции.

Проверки: tests/Unit/Contract/ContractDocumentLayoutTest.php (без БД); сохранение prepare/create/read проверяется совместным ContractTemplateCardIntegrationTest. API прав, фиксация версий и схемы значений не меняются.
