# Справка КС-3 по набору актов

Справка КС-3 собирает утверждённые и подписанные акты КС-2 одного договора за период в один документ. После утверждения состав, суммы, ставка и сумма НДС, накопления по строкам основания и итоги замораживаются. Новые акты и аннулирование исходных КС-2 не пересчитывают утверждённую или подписанную справку.

Печатные формы КС-2 отдельных актов не меняются. КС-6а — отдельный накопительный регистр: факт берётся из выполненных работ, актирование — из строк утверждённых актов.

Версия расчёта: `ks3-v1`.

## Статусы

| Статус | Смысл |
| --- | --- |
| `draft` | Черновик. Экспорт строится из текущего расчёта, на форме пометка «ЧЕРНОВИК». Утверждающего нет. |
| `approved` | Утверждена. Экспорт PDF и Excel строится только из сохранённого снимка. |
| `signed` | Зарегистрирован подписанный оригинал файла (`signed_file_id`). Суммы не меняются. |
| `annulled` | Справка аннулирована. Состав сохраняется как исторический снимок. |

Признак `has_annulled_acts` означает, что один или несколько актов состава позже аннулированы. Снимок справки при этом не пересчитывается. Исправляющая версия создаётся явно новым запросом с новым ключом операции.

## Что фиксируется в снимке

- Период (`period_start` / `period_end`), номер и `version_number`.
- `source_act_ids` и `composition`: идентификаторы актов, сохранённые суммы, НДС, ставка, даты выполнения и подписи каждого акта.
- `snapshot` / `totals`: накопления по устойчивому ключу строки основания (`estimate:{id}`, `work:{id}`, `line:{id}`) — с начала строительства, с начала года, за отчётный период — плюс итог и НДС.
- `performed_at` — дата выполнения (конец периода); `document_date` — дата составления/подписи документа. Это разные поля.
- `calculation_version` на момент утверждения.

Один акт входит в одну утверждённую справку ровно один раз (`is_binding`). Повторное включение того же акта возвращает 422.

Черновики с `project_id = NULL` различаются частичным уникальным индексом по договору, периоду и номеру версии: два пустых проекта не считаются разными записями.

## Контракт API

Базовый префикс: `/api/v1/admin/act-reports`.

- `POST contract-period-certificates` — создать черновик. Право `act_reports.create`.
- `GET contract-period-certificates/{id}` — прочитать справку. Право `act_reports.view`.
- `POST contract-period-certificates/{id}/approve` — утвердить и заморозить снимок. Право `act_reports.approve`.
- `GET contract-period-certificates/{id}/export/ks3` — Excel из снимка (для черновика — из текущего расчёта). Право `act_reports.export.excel`.
- `GET contract-period-certificates/{id}/export/ks3/pdf` — PDF из того же набора данных. Право `act_reports.export.pdf`.

Ключ идемпотентности обязателен: поле `idempotency_key` или заголовок `Idempotency-Key` (8–128 символов). Повтор с тем же телом возвращает исходную справку. Изменённое тело с тем же ключом — 409.

Тело POST:

```json
{
  "contract_id": 1,
  "project_id": null,
  "period_start": "2026-01-01",
  "period_end": "2026-01-31",
  "document_date": "2026-02-03",
  "act_ids": [10, 11],
  "idempotency_key": "ks3-january-v1"
}
```

`act_ids` необязателен: без списка в справку входят все утверждённые и подписанные акты договора (и проекта, если задан) с датой периода `COALESCE(period_end, act_date)` внутри интервала. Пустой период — 422.

Ответ — `AdminResponse` с ресурсом справки: статус, состав, снимок, итоги, даты, `has_annulled_acts`, `is_frozen`.

Регистрация подписанного файла выполняется сервисом `ContractPeriodCertificateService::markSigned`: файл организации с категорией `signed_certificate`, привязанный к справке. HTTP-загрузка оригинала для UI — отдельный шаг рабочего места (T25). Печатные КС-2 актов по-прежнему используют существующий `POST {act}/signed-file`.

## Аннулирование актов

Аннулирование КС-2 идёт прежним маршрутом `POST {act}/annul`. Если акт входил в утверждённую или подписанную справку, состав и суммы справки не меняются, выставляется `has_annulled_acts`. Новая справка за тот же период получает следующий `version_number`; уже связанные акты в неё не входят.

## КС-6а

`GET /api/v1/admin/contracts/{contract}/export-ks6a`

Параметры: `format` = `pdf` или `xlsx`; `period_start` и `period_end` задаются вместе. Без периода берутся месяцы по данным договора.

Колонки по каждому месяцу периода без сжатия: «выполнено (факт)» из выполненных работ и «актировано» из строк утверждённых/подписанных актов. Остаток считается отдельно по факту и по актированию. Строки с одинаковым названием и разным основанием не сливаются. PDF печатает по два месяца на страницу с продолжениями.
