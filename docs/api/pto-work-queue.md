# Очередь рабочего места ПТО

`GET /api/v1/admin/pto/work-queue` возвращает страницу действий специалиста ПТО. Доступны только проекты, которые сервер считает доступными текущему пользователю: клиентский список проектов не расширяет выборку. Право `executive-documentation.view`, модуль исполнительной документации активен.

## Параметры

- `project_id` — один доступный проект; недоступный идентификатор даёт пустую страницу, а не чужие строки.
- `category`: `risk`, `problem`, `blocker`, `task`.
- `queue`: `mine`, `waiting`, `unassigned`, `overdue`, `risks`, `returns`, `incomplete`.
- `responsible_user_id`, `action`, `horizon_days` (1–90, по умолчанию 14), `page`, `per_page` (1–100, по умолчанию 25).

Ответ — `data` со строками, плоские `meta` пагинации и `summary` со счётчиками: `blocker`, `problem`, `risk`, `task`, `mine`, `waiting`, `unassigned`, `overdue`, `returns`, `incomplete`, `computed_at`. Одна исходная позиция имеет один `source_key` и не увеличивает несколько категорий сразу.

## Категории

| Категория | Смысл | Как снимается |
| --- | --- | --- |
| `blocker` | Нет обязательного документа или подписи из ожидаемого состава | Выполнено требование, сервер пересчитал готовность |
| `problem` | Возвращённый комплект или открытое замечание | Исправление в исходном процессе |
| `risk` | Ближайшая работа по графику без готового комплекта | Появилась дата и комплект либо принято ответственное решение |
| `task` | Назначенное действие, в том числе автоматически возникшее требование | Проверяемый результат; отметка «готово» не снимает блокировку подписи |

Если у ближайшей работы нет даты, строка помечается `data_complete=false` и `priority_basis.type=incomplete_data`. Это не риск и не просрочка. Пустой срок показывается как «Срок не назначен», `overdue=false`.

Строка содержит источник, основание приоритета, ответственного, ожидание, следующее действие и ссылки: комплект, документ, редакция, требование, факт, журнал, ведомость объёмов, ревизия чертежа, партия, передача, задача графика. Стоимости, цены и суммы не включаются.

## Комплектность

`GET /api/v1/admin/pto/completeness` — ожидаемый состав по доступным проектам, те же `page`/`per_page`/`project_id`. Счётчики те же, что у очереди. У каждой позиции свой `source_key` требования.

## Задачи

Назначения и сроки хранятся в механизме задач рабочего места (`pto_workspace_tasks`) с уникальным `(organization_id, source_key)`.

- `POST /api/v1/admin/pto/tasks` создаёт или обновляет задачу. Автоматическое требование и ручное добавление с тем же ключом — одна запись.
- `POST /api/v1/admin/pto/tasks/{id}/complete` отмечает задачу выполненной. Блокировка подписи при этом не снимается: исчезнуть она может только после допустимого подписания и пересчёта требований.

Очередь при чтении синхронизирует открытые требования в задачи, не копируя факты и документы.
