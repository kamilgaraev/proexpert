# Нормы расхода, факт расхода и отчёт М-29

Списание со склада (М-11, акт списания, движение `write_off`) — это отпуск. Нормативный расход на принятый объём работ считается отдельно: утверждённая норма × принятый объём, факт расхода, отклонение и причина. Складские формы М-4, М-7, М-8, М-11, М-15, М-17, ИНВ-3 и акты списания не переписываются.

Версия расчёта отчёта: `m29-v1`. Каталог официальных документов: `official_material_usage_m29`, статус публикации `candidate` (renderer есть; полная юридическая публикация не заявляется).

## Сущности

### Утверждённая норма расхода (`material_consumption_rates`)

Материал × вид работы (опционально позиция сметы/ВОР) × единица работы. Количество материала на единицу работы, единица материала, версия, даты действия, основание (ГЭСН / проект / техкарта — текст и необязательная ссылка на документ ИТД).

Справочник `work_type_materials.default_quantity` остаётся каталожной подсказкой и сам по себе не является утверждённой нормой для М-29.

Изменение нормы создаёт новую версию. Уже утверждённый или подписанный отчёт хранит снимок и не пересчитывается.

### Факт расхода (`material_consumption_facts`)

Связан с выполненной работой (`completed_works`), утверждённой нормой, опционально с партией (`batch_number` склада), документом качества (паспорт/сертификат ИТД) и складским отпуском (`warehouse_movements`).

Виды: `consumption` и `return`. Возврат уменьшает чистый расход. Повтор с тем же `operation_key` и тем же телом идемпотентен; другое тело — 409. Факт не создаёт и не дублирует складское списание.

Отпущено и израсходовано — разные величины. Остаток на площадке = отпуск по связанным движениям минус чистый расход (если отпуск связан).

### Отчёт М-29 (`material_consumption_statements`)

Период, объект (проект), необязательный договор. Статусы: `draft` / `approved` / `signed`. После утверждения снимок JSONB заморожен. Подписанный файл регистрируется сервисом `markSigned` (HTTP загрузки — рабочее место, T25).

Строка отчёта: материал × работа. Норма на единицу, принятый объём, нормативный расход, фактический расход, отклонение (+перерасход / −экономия), причина и согласование, основание нормы. Принятый объём: сумма технической приёмки по работе, иначе каноническое физическое количество факта работы.

Отчёт нельзя утвердить, если для строки нет утверждённой нормы или факт расхода не связан с работой: 422, русское сообщение и список причин.

## Смешанные единицы

Норма и факт приводятся к единице нормы только при явном коэффициенте (`conversion.coefficient` + `reason`). Без коэффициента сравнение блокируется. Молчаливого пересчёта «т ↔ кг ↔ мешок» нет.

## Контракт API

Базовый префикс: `/api/v1/admin/material-consumption`.

Права: чтение `materials.consumption_rates.view`, запись `materials.consumption_rates.edit`, экспорт `materials.export`.

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `rates` | Черновик нормы. Ключ идемпотентности обязателен. |
| POST | `rates/{id}/approve` | Утвердить норму. |
| GET | `rates/{id}` | Прочитать норму. |
| POST | `facts` | Факт расхода или возврата. |
| GET | `facts/{id}` | Прочитать факт. |
| POST | `statements` | Черновик М-29 за период. |
| GET | `statements/{id}` | Прочитать отчёт, включая `blockers` и `is_ready`. |
| POST | `statements/{id}/approve` | Утвердить и заморозить снимок. |
| GET | `statements/{id}/export/xlsx` | Excel. |
| GET | `statements/{id}/export/pdf` | PDF из того же набора данных. |

Ключ идемпотентности: поле `idempotency_key` / `operation_key` или заголовок `Idempotency-Key` (8–128 символов).

### Норма

```json
{
  "project_id": 1,
  "material_id": 10,
  "work_type_id": 3,
  "estimate_item_id": null,
  "work_unit_id": 4,
  "material_unit_id": 5,
  "quantity_per_work_unit": "2",
  "basis_kind": "gesn",
  "basis_text": "ГЭСН 08-02-001",
  "basis_document_id": null,
  "effective_from": "2026-01-01",
  "idempotency_key": "rate-cement-v1"
}
```

`basis_kind`: `gesn`, `project`, `tech_card`.

### Факт

```json
{
  "completed_work_id": 42,
  "material_id": 10,
  "kind": "consumption",
  "quantity": "170",
  "unit_id": 5,
  "occurred_on": "2026-01-20",
  "warehouse_movement_id": 88,
  "batch_number": "П-12",
  "quality_document_id": 15,
  "deviation_reason": "Перерасход из-за потерь при укладке",
  "agreed_by_user_id": 7,
  "conversion": { "coefficient": "1", "reason": "единица нормы" },
  "operation_key": "cons-work-42-v1"
}
```

`conversion` обязателен, если единица факта не совпадает с единицей нормы.

## Печатная форма М-29

Ориентир: типовая межотраслевая форма М-29 (утв. ЦСУ СССР 24.11.1982 № 613).

Печатаются:

- титул: организация, объект, прораб (если передан), период;
- раздел I «Нормативная потребность»: наименование работ, единица, объём, наименование материалов, норма на единицу, нормативная потребность;
- раздел II «Сопоставление фактического расхода с нормами»: расход по норме, фактический расход, экономия, перерасход, причины.

### Требует сверки с первоисточником

Не выдумывались и в файле не заполняются как достоверные реквизиты:

- код по ОКУД / ОКПО и точная шапка углового штампа;
- нумерация граф и подтабличные примечания бланка 1982 года;
- состав и порядок подписей (прораб, начальник участка, проверяющий) — выводятся пустые строки без утверждения, что это полный бланк;
- складские остатки на начало/конец и приход (их нет в разделах I–II этой реализации; оборот склада остаётся в М-11 / карточках склада);
- печать «электронного» экземпляра и машиночитаемая подпись.

## Связь со складом

| Форма | Смысл | Отношение к М-29 |
| --- | --- | --- |
| М-11 | Требование-накладная, отпуск | Ссылка `warehouse_movement_id`, не факт расхода |
| Акт списания | Списание недостачи/порчи/утилизации | Не нормативный расход на объём |
| М-4, М-7, М-8, М-15, М-17, ИНВ-3 | Складской учёт | Без изменений |

Повторное проведение журнального списания по-прежнему идемпотентно на складе и не создаёт второй расход в М-29, пока не записан отдельный факт с новым ключом.
