# Количественная приёмка и комплект передачи

Статус: T17 реализована в рабочей ветке и проверена целевыми тестами. Не опубликовано. Проверка реального комплекта ПТО в T16 остаётся отдельным условием итоговой приёмки.

## Предъявление объёмов

`PUT /api/v1/admin/handover-acceptance/scopes/{scope}/work-quantities` требует `handover-acceptance.edit`. Тело: `expected_revision`, уникальный `operation_key`, `lines`. Каждая строка содержит `completed_work_id`, `unit_id` и строковые десятичные значения `presented_quantity`, `accepted_quantity`, `defect_quantity`. При ненулевом дефектном остатке требуется `defect_reason`.

Предъявленный объём равен сумме принятого и дефектного. Хранение сохраняет шесть знаков после запятой. Единицу сверяет сервер с источником факта. Факт нельзя распределить по нескольким зонам сверх его количества. После приёмки или передачи изменение объёмов требует отдельного возврата зоны в работу; предыдущий снимок решения сохраняется.

Режим договора `settings.technical_acceptance.mode = accepted_only` ограничивает актирование технически принятой частью. Из неё вычитаются резервы других актов. Предварительная доступность и команда используют одинаковый предел; повторная проверка выполняется при подаче и согласовании акта. Четырёхзначный контракт актирования округляет доступный остаток вниз, при этом исходный технически принятый объём возвращается с шестью знаками.

## Исполнительные документы

Пакет передачи может ссылаться на `executive_document_set_id`. Позиция пакета ссылается на `executive_document_version_id`; копия карточки или файла ИД не создаётся. Сервер проверяет организацию, проект, комплект, тип документа, согласованную актуальную редакцию и её контрольную сумму.

Связанный комплект проверяется относительно ожидаемого состава ИД. Отсутствующая обязательная позиция блокирует приёмку; мотивированное решение «не применимо», оформленное с правом согласования в ИТД, не блокирует её. Обычная загрузка дополнительного файла оставляет его черновиком. Для ИД следует выбрать каноническую редакцию, а не загрузить её повторно в пакет.

Одинаковая проверка используется в предварительной готовности, при приёмке и при передаче. Команда повторяет проверку в транзакции. Решение сохраняет снимок редакций документов, требований и количеств. Новая редакция ИД не переписывает прошлый снимок и требует повторной проверки текущей передачи.

Это внутренний учёт проверки и приёмки. Юридически значимое подписание и официальный комплект оформления рассматриваются отдельно в T19.

После технической приёмки можно подготовить или дополнить пакет для передачи заказчику. Сохранённый снимок технической приёмки от этого не меняется; при передаче проверяется текущий пакет. Переданный пакет изменяется только после возврата зоны в работу.
