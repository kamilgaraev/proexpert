# Списки файлов и получение ссылки для скачивания

Списки Personal Files и Report Files принимают `page` и `per_page` и возвращают `meta.current_page`, `meta.last_page`, `meta.per_page`, `meta.total`. Лимит страницы остаётся от 1 до 100; значение по умолчанию — 15. При равенстве выбранного поля сортировки строки дополнительно упорядочиваются по `id` в том же направлении.

Каждая страница читается отдельным запросом. Параллельные добавления или удаления могут смещать границы страниц; обновление списка начинает чтение заново. Страницы не образуют единый снимок данных.

Административные `GET /api/v1/admin/personal-files` и `GET /api/v1/admin/report-files` принимают необязательный boolean-параметр `include_download_urls`. Для query string используйте `0` или `1`.

Без параметра или с `include_download_urls=1` сохраняется прежнее поведение: сервер формирует ссылки для каждой строки списка. При `include_download_urls=0` возвращаются те же строки, поля, сортировка и пагинация, но `download_url` равен `null`. Сервер не классифицирует отчёты и не запрашивает ссылки из хранилища. Проверки доступа к содержимому выполняются при запросе ссылки на выбранный файл.

Получение ссылки:

- `GET /api/v1/admin/personal-files/{id}/download-url`
- `GET /api/v1/admin/report-files/{id}/download-url`

`id` — идентификатор строки соответствующего списка, не путь к объекту. Требуется обычная административная аутентификация и контекст организации. Report Files дополнительно сохраняет право `report_files.view`. Поиск ограничен текущим владельцем и организацией; для Report Files сохраняется поддержка принадлежащих этому владельцу старых строк без `organization_id`.

Успешный ответ использует `AdminResponse`:

```json
{
  "success": true,
  "message": "Файл найден.",
  "data": {
    "download_url": "..."
  }
}
```

Ответ ссылки имеет `Cache-Control: no-store`. Клиент запрашивает её заново при каждом скачивании. Для отчётов помощника новые административные endpoint возвращают `/api/v1/admin/ai-assistant/reports/{token}/download`; этот URL принимает ту же административную аутентификацию без подстановки другого маршрута. Прежний формат ссылок в списках по умолчанию сохраняется. `null` в списке, полученном с `include_download_urls=0`, не означает отказ в доступе.

Отсутствующая или чужая строка, папка Personal Files и отсутствующий обычный объект Report Files возвращают 404. Отказ текущих проверок доступа к отчёту возвращает 403; истёкший grant отчёта — 410. Техническая ошибка возвращает стандартный ответ с кодом 500. Отказ проверки отчёта не переключает скачивание на обычную ссылку S3.

Для отчётов помощника сервер выполняет прежние проверки срока, организации, доменов и ссылок перед выдачей URL. Существующий download endpoint независимо повторяет их при скачивании. Отзыв доступа после выдачи ссылки не разрешает чтение отчёта по старой ссылке. Обычные файлы сохраняют прежние алгоритмы: Report Files проверяет наличие объекта перед подписанием URL, Personal Files использует `FileService::temporaryDownloadUrl`.
