# Переделка и повторная техническая приёмка

Статус: T18 реализована в рабочей ветке. Целевые проверки расчёта, прав, истории, API, замечаний и повторной приёмки пройдены; независимое ревью выполнено. В рабочую систему изменения не выпущены.

## Что учитывается

Участок переделки связан со строкой предъявленного объёма, её исходной единицей измерения и ответственным. Это не новая выполненная работа. Для факта 100 с приёмкой 80 и недостатками на 20 запись переделки не изменяет факт и не отменяет принятие 80. После проверки исправленных 20 принятый объём становится 100, дефектный остаток — 0. Старое решение о приёмке 80 сохраняется.

Несколько недостатков на одном участке связываются с одной записью переделки. Их количества не складываются повторно. Разные участки переделки резервируют разные части остатка с недостатками; суммарный резерв не может его превысить. Допускаются две последовательные проверки по 10 вместо одной на 20.

## Операции API

Все адреса начинаются с `/api/v1/admin/handover-acceptance`.

| Операция | Адрес | Право |
| --- | --- | --- |
| Список переделок зоны | `GET /scopes/{scope}/reworks` | `handover-acceptance.view` |
| Создание участка | `POST /scopes/{scope}/reworks` | `handover-acceptance.edit` |
| Предъявление исправления | `POST /reworks/{rework}/submit` | `handover-acceptance.edit` |
| Повторная проверка | `POST /reworks/{rework}/verify` | `handover-acceptance.approve` |
| История действий | `GET /reworks/{rework}/history` | `handover-acceptance.view` |

Создание принимает `quantity_line_id`, строковое `quantity`, `responsible_user_id`, `reason`, `expected_revision` строки количества и `operation_key`. Предъявление принимает редакцию переделки, ключ операции, описание исправления и список `evidence_file_ids`. Проверка принимает редакцию переделки, ключ операции, `decision` (`accepted` или `rejected`) и комментарий. Списки и история выдаются постранично, по 50 записей.

Состояния: `open → submitted → accepted`; при отказе `submitted → rejected → submitted`. Отказ не прибавляет принятый объём. Повтор успешного запроса возвращает его исходный результат. Изменение порядка полей JSON не создаёт другую операцию; другое содержимое, автор или назначение ключа вызывает конфликт. Устаревшая редакция отклоняется. Операции сохраняются в журнале, изменение и удаление событий запрещены также на уровне БД.

## Замечания и доказательства

В существующую операцию создания замечания можно передать `work_rework_id` своей зоны. Связанные с переделкой замечания не отнимают ранее принятый объём. Каждое замечание проверяется отдельно; закрытие одного не закрывает остальные. Закрытие замечания переделки требует права согласования и предъявленного исправления. Повторная приёмка запрещена, пока хотя бы одно замечание открыто. Если создан отдельный дефект контроля качества, его собственная проверка устранения тоже должна быть завершена; закрытие замечания приёмки её не заменяет.

Доказательства включают описание исправления и необязательные существующие файлы своей организации, относящиеся к этой работе, зоне, проекту или записи переделки. Сохраняются ссылки и снимок реквизитов файлов. Это не утверждение о наличии электронной подписи или проверке содержимого файла. В публичном ответе нет внутренних путей и имени хранилища.

Единица измерения фиксируется при создании. Изменение единицы или исходного факта требует сверки, а не автоматического переосмысления объёма переделки. Незавершённые переделки блокируют окончательную передачу зоны. Техническая приёмка исправной части остаётся отдельным действием.

## Финансовые последствия

Для связанных согласованных или подписанных актов показывается необходимость проверить влияние исправления на расчёты. В снимке сохраняются акт, статус, объём, сумма и источник связи. Каноническая строка акта имеет приоритет над старой связью для той же пары акт/работа, поэтому объём не удваивается. Неизвестные исторические суммы и количества отмечаются явно.

Флаг не означает автоматического уменьшения стоимости: разные недостатки одной работы могут относиться к разным участкам. Финансовое решение принимается отдельно. Переделка не изменяет подписанный акт, его строки, исходный производственный факт или предыдущие решения о приёмке.
