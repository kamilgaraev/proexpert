# Общий журнал: подготовка бумажного документа

Режим `paper_preparation` формирует проект общего журнала по структуре приказа Минстроя № 1026/пр. Он не означает ведение электронного общего журнала: XML, электронное подписание записей, регистрация в органе надзора и хранение в течение жизненного цикла объекта этим режимом не подтверждаются. Печатный проект требует проверки уполномоченными участниками и оформления бумажного экземпляра.

Нормативное основание: [официальное опубликование приказа](https://publication.pravo.gov.ru/document/0001202212300009). Проверяемое соответствие разделов, источников, ответственных и правил исправления: `general-journal-1026-field-map.md`. В форме шесть разделов. Наименование старой выгрузки исправлено на «Оперативный отчёт о выполнении работ»; старые маршруты `export/ks6` и ранее выданные файлы сохраняются. КС-6а — отдельный накопительный регистр.

## Источники и ответственность

| Часть | Источник | Проверка ответственным участником |
| --- | --- | --- |
| Титульный лист | Номер журнала, объект, адрес, период из журнала и проекта; реквизиты организаций, разрешения, экспертизы, полномочия из `profile.header` и `profile.representatives` | Участники подтверждают свои реквизиты и полномочия; принадлежность организации к роли не назначается автоматически |
| Изменения титула | `profile.title_changes` | Дата, содержание и основание изменения, представитель и полномочия; бумажная подпись оформляется отдельно |
| 1. Инженерно-технический персонал | `profile.sections.1` | Организация, сотрудник и должность, начало с видом работ, окончание, уполномоченный представитель |
| 2. Специальные журналы | `profile.sections.2` | Наименование и выдача, лицо, ведущее журнал, передача и получатель |
| 3. Выполнение работ | Только согласованные записи выбранного журнала; уточнения `work_details` привязаны к их ID | Дата, условия, место, методы, материалы, испытания и представитель. Условия — отдельная графа. Создатель записи не считается подписантом автоматически |
| 4. Строительный контроль | `profile.sections.4` | Контроль, недостатки, срок устранения, представитель заказчика, фактическое устранение и проверка |
| 5. Реестр ИД | Явно выбранные `document_version_ids` того же объекта и организации с доказательством подписи точной версии | Наименование и реквизиты замороженной версии, дата и подписанты. Согласование не заменяет подпись |
| 6. Государственный надзор | `profile.sections.6` | Мероприятие, дата, срок устранения, инспектор, фактическое устранение и проверка |

Разделы 1, 2, 4 и 6 в данном режиме заполняет уполномоченный пользователь по исходным документам. Они не выдаются за автоматически синхронизированные реестры кадров, контроля или надзора. Незавершённые поля остаются пустыми для проверки и оформления. Отсутствующие данные не подменяются вымышленными сведениями.

Порядок 1026/пр предусматривает своевременное внесение сведений ответственными лицами: сведения о работах — в день выполнения; ряд сведений о контроле, подписанной ИД и надзоре — не позднее следующего дня. Генерация проекта из накопленных данных не подтверждает соблюдение этих сроков. Исправление бумажного экземпляра выполняется по применимому порядку, с сохранением читаемого первоначального содержания и удостоверением исправления.

## Контракт API

Маршруты в `/api/v1/admin/construction-journals/{journal}`:

- `GET general-document`: описание полей, последняя редакция и 50 последних записей истории.
- `GET general-document/versions/{versionId}`: конкретная сохранённая редакция в области этого журнала. Более ранние редакции доступны по `previous_version_id`.
- `POST export/general`: сохранить редакцию и поставить PDF в существующую очередь выгрузок.

Тело POST:

```json
{
  "mode": "paper_preparation",
  "expected_revision": 0,
  "operation_key": "journal-paper-unique-operation",
  "correction_reason": null,
  "profile": {
    "header": {},
    "representatives": {},
    "title_changes": [],
    "sections": {"1": [], "2": [], "4": [], "6": []}
  },
  "work_details": [],
  "document_version_ids": []
}
```

Точные ключи титула, групп представителей и граф разделов возвращает GET. Уточнение работы содержит `entry_id`, `conditions`, `location`, `methods`, `materials`, `tests`, `representative_name`, `representative_position`. Разделы 3 и 5 клиент напрямую не заменяет.

Ответ 202 содержит `version` и `export`. Состояние очереди читается существующим `GET /api/v1/admin/construction-journal-exports/{export}`. Ссылка на файл выдаётся после завершения. Хранение — приватное, в области организации.

## Редакции и повторные запросы

Первая редакция требует `expected_revision=0`. Следующая требует текущий номер и непустую причину исправления. Устаревшая редакция возвращает 409. Повтор той же операции с тем же телом возвращает прежнюю редакцию; изменённое тело с тем же ключом отклоняется.

Редакция хранит снимок данных, их SHA-256, версию шаблона, автора, дату и ссылку на предыдущую редакцию. PostgreSQL запрещает UPDATE и DELETE сохранённых редакций. Изменения исходного проекта или работ не переносятся задним числом в ранее сохранённый документ. Задание очереди читает сохранённый снимок, а не актуальные работы.

Регистрация бумажного оригинала или проверенной электронной подписи ИД остаётся в существующем юридическом архиве. Новый общий журнал не создаёт подписи за участников. Наличие зарегистрированной подписи не заменяет проверку полноты необходимого состава подписантов ответственным ПТО.

## Специальные журналы

Доступны отдельные профили сварочных, бетонных, свайных, монтажных, антикоррозионных работ и авторского надзора. Для каждого фиксируются номер, период, ответственный, нормативное основание и основание применимости, а также предметные сведения. Профиль авторского надзора не требует обязательной привязки к виду строительных работ. Режим `external_manual_review` означает регистрацию и проверку внешнего журнала, а не электронное ведение по нормативной схеме.
