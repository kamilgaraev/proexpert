# Материалы по статье

В редакторе статьи через меню добавления блока выберите «Материалы по статье». Загрузите PDF, DOCX или XLSX до 10 МБ либо выберите уже загруженный документ из медиатеки. Укажите название для читателя и необязательное описание. В одном блоке можно разместить до 10 документов.

После сохранения блок содержит доверенные сведения из медиатеки: адрес, имя файла, формат и размер. Повторный выбор документа не загружает новую копию. Открепление удаляет только связь со статьёй; файл остаётся доступным для повторного использования. Используемый файл нельзя удалить через медиатеку.

Документы загружаются через FileService в S3, в каталог организации платформенного контента `cms/blog/media`. Локальный временный файл после загрузки из редактора удаляется. Прикрепляемые материалы публичны: не размещайте в них внутренние документы клиентов.

Проверяются серверный MIME, расширение, структура DOCX/XLSX, отсутствие VBA-макросов и размер. Право на загрузку — существующее `system_admin.blog.media.upload`, доступ к редактору — право изменения статьи. Материалы других контекстов и произвольные внешние ссылки не принимаются.

Блок хранится в `editor_document`, входит в существующие версии статьи и выводится в её HTML. Оформление публичных карточек находится в стилях маркетингового блога.

Штатная миграция создаёт отдельную организацию «МОСТ — медиатека сайта» с уникальным `system_key=platform_media_library`, без реквизитов, сотрудников и проектов, с отключённым клиентским доступом. Медиатека использует её автоматически, если `PLATFORM_CONTENT_ORGANIZATION_ID` не задан. Явно заданный ID имеет приоритет; ошибочный ID не переключает владельца файлов. Служебный ключ не доступен для массового назначения из клиентских форм. Повторный запуск миграции не создаёт дубликат. Откат этой миграции запрещён: смена владельца выполняется отдельной прямой миграцией, чтобы не потерять связь с файлами S3.

Проверки: BlogMediaLibraryTest, BlogCmsEditorWorkflowTest, BlogInlineBlockEditorCatalogTest, BlogDocumentRendererTest; клиентские состояния — `node --test tests/Frontend/blog-inline-materials.test.mjs`. Для PHP-тестов используется штатный PostgreSQL launcher.
