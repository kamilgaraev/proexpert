# Записанный транспорт для интеграционной проверки

Эти ответы синтетические. Они проверяют совместимость production pipeline с сохранённым HTTP-контрактом и не являются независимым сметным эталоном или замером качества Luna.

`text-partial-v1.json` содержит ответы составителя и аудитора в формате HTTP chat completions. Единственная явная подстановка `__description_fact_id__` связывается с текущим каноническим фактом первоначального описания. SHA256 descriptor проверяется до создания сессии. Отсутствующий ответ не вызывает сетевой fallback.

В тесте используются настоящие права, product entitlement, общий кошелёк, quote/reserve, Timeweb SDK/parser, девять стадий, publication, журнал расходов и replay. Подменяются только Guzzle/S3 HTTP. Adapter доступен только в canonical PostgreSQL16 test namespace и не регистрируется в production service provider.

`expected-partial-v1.json` проверяет сохранение неизвестных чисел и наличие работы из записи. Он не утверждает полноту всех автоматически предложенных работ. `counterfactual-oracle.json` намеренно содержит неверную работу: это проверка отсутствия зависимости prediction от oracle. Два одинаковых текстовых входа имеют разные locators, как требует действующий manifest contract.

Benchmark читает oracle после выполнения adapter. Стоимость берётся из настоящего журнала attempts с их тарифными снимками. Синтетические100 входных и50 выходных токенов каждого из двух ответов дают0,00945₽ при текущем тарифе; это математическая проверка журнала, не себестоимость пользовательской сметы. Неоценённый состав не списывает единицы пользователя. Повтор не создаёт новые вызовы, расходы или ревизии.

`photo-no-scale-v1.json` добавляет фото без масштаба. Тест генерирует обезличенный PNG и проходит настоящий upload, manifest, отдельный documents quote/reserve, Vision HTTP/parser, публикацию, подтверждение просмотра входа и запуск оценки. Ответы наблюдателей сохраняют пустые размеры и факты; страница служит источником, а не доказательством объёма. На границе HTTP проверяется отдельный владелец физической попытки, выбранный провайдером. Повтор не отправляет запросы. Известный расход синтетических вызовов учитывается, неоценённый состав не списывает пользовательские единицы.

Здесь проверяются текстовый неполный ремонтный состав и контрактный путь фото без масштаба. Другие документы, CAD/XLSX и промышленность требуют собственных случаев и отдельно проверенных предметных эталонов. `accuracy_calibrated=false` сохраняется.

`photo-no-scale-v1.json` содержит введённое пользователем описание окраски. Оно служит основанием предлагаемой работы; синтетический PNG не доказывает распознавание окраски.

`photo-only-empty-context-v1.json` проверяет отдельный случай без описания, размеров и распознанных фактов. Пользователь выбирает ремонтный профиль и раздел отделки. Составитель возвращает пустой список дополнительных работ; сервер сохраняет базовый состав выбранного раздела, неизвестные объёмы и цены, вопросы и запрет применения. Факт первоначального описания не создаётся. Такой результат проверяет механизм предварительного состава по выбранному разделу, а не качество распознавания фотографии или самостоятельное определение её назначения.
