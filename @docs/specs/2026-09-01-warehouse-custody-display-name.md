# Человекочитаемое название склада ответственного

## Проблема

Склад ответственного сохраняет техническое имя учётной записи внутри названия. Оно попадает в общий переключатель складов и раскрывает пользователю служебный логин вместо ФИО.

## Ожидаемое поведение

- обычные названия складов не изменяются;
- для склада ответственного имя строится из названия объекта и ФИО сотрудника, действовавшего на дату создания склада;
- при отсутствии кадрового профиля показывается `ФИО не указано`, технический логин не используется;
- существующие записи с логином исправляются на уровне ответа без изменения production-данных;
- новые склады ответственных сразу получают человекочитаемое название;
- список остаётся ограничен текущей организацией и не получает N+1-запросов к кадровым данным.

## Проверки

- API-регрессия списка складов с кадровым профилем и без него;
- обычный склад сохраняет исходное название;
- целевой PostgreSQL-прогон, Pint, PHPStan и проверка синтаксиса;
- production-проверка переключателя складов владельцем после штатного релиза.
