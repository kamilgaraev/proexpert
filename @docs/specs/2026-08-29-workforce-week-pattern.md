# Недельный график персонала

## Проблема

График работы хранит `schedule_type`, `hours_per_day` и `week_pattern`, но календарь персонала учитывает только отдельные исключения по датам. Если исключение отсутствует, любой день недели считается рабочим. Админка при создании графика не отправляет недельный шаблон и показывает обязательную по смыслу «дату первого дня», которая фактически создаёт только одно исключение.

## Бизнес-контракт

- Базовый график задаётся днями недели по ISO: понедельник — `1`, воскресенье — `7`.
- Тип `weekly` без явного шаблона означает безопасный стандарт 5/2: понедельник–пятница.
- Поддерживаются готовые варианты 5/2, 6/1 и ежедневный график.
- `week_pattern.work_days` имеет приоритет над стандартом типа графика.
- Отдельный календарный день имеет приоритет над недельным шаблоном и может быть рабочим, выходным или праздничным.
- Существующие графики `weekly` без шаблона начинают корректно считать субботу и воскресенье выходными без миграции данных.
- Неизвестный исторический тип сохраняет прежнее поведение «каждый день рабочий», чтобы не менять его смысл молча.

## API

Создание и обновление графика принимает:

```json
{
  "code": "OFFICE-5-2",
  "name": "Офис 5/2",
  "schedule_type": "weekly",
  "hours_per_day": 8,
  "week_pattern": {
    "work_days": [1, 2, 3, 4, 5]
  }
}
```

`week_pattern.work_days` — непустой список уникальных целых чисел от 1 до 7.

## Состояния UI

- В форме видны код, название, вариант недели и часы рабочего дня.
- По умолчанию выбран вариант 5/2.
- Особая дата необязательна и явно названа исключением, а не первым днём повторяющегося графика.
- Если особая дата не заполнена, создаётся только недельный график.
- Если заполнена, после графика создаётся одно датированное исключение.

## Проверки

- Backend-регрессия: `weekly`/5/2 показывает будни рабочими, выходные выходными; явный рабочий день в субботу переопределяет шаблон.
- Backend-валидация: недопустимые номера и дубли дней отклоняются с 422.
- Admin unit/component test: форма отправляет тип `weekly`, выбранные дни недели и не создаёт исключение без даты.
- Production smoke: существующий график сотрудника показывает 5–6 сентября 2026 года выходными, а 1 сентября — рабочим по явному исключению.

## Риски

- Payroll и отчёты используют тот же `week_pattern`; календарь должен читать его в совместимом формате, не создавать второй формат.
- Изменение стандарта применяется только к известному `weekly`; неизвестные исторические типы не переопределяются.
- Миграции не требуются.
